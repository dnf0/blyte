# V1 map trial: the system and data map, from code, in the mock

Date: 2026-11-20. Spec: `docs/specs/2026-11-20-blyte-v1.md`, decision 4 and "Order of work"
step 4, moved forward as a trial. Builds on `docs/plans/2026-11-20-v1-mock.md`.

## Goal

The mock's right-hand pane shows a real map of each repository in the replay: its units and
the dependencies between them (system), its data structures and where they are used (data), and
the replayed runs lit on the units they change. A guide walks through every part of the surface.

## Decisions

- **The map is extracted by blyte from source files**, with no build and no other program:
  Rust through manifests (`toml`) and `syn`; Python through a line scanner. Research run R-MAP1
  (2026-11-20) tried both: on this repository 60 modules and 145 edges with none unresolved; on a
  Python repository 91 of 91 import edges and 10 of 10 dataclasses matched Python's own parser.
- **Only what is written in the code is shown.** A reference counts when the name is written
  (a `use`, a path, an import). A module that uses a structure only through an inferred type is
  not listed as referring to it. The page says so.
- **Left out, because they cannot be extracted reliably:** the files a program writes, items
  made by macros, paths inside macro arguments, dynamic imports, and which names a glob import
  brings in (the module edge is still drawn).
- **Nothing is guessed.** A file that does not parse is listed under `unparsed`; an internal
  reference that does not resolve is listed under `unresolved`; the page shows both counts. A
  repository with neither Rust nor Python gets an error that says so, not an empty map.
- **Readable size.** Groups (crates, packages) are drawn collapsed; one group is open at a time.
  The data view shows serialisable structures by default.
- **Overlay.** A changed file that is a unit's file lights the unit; any other file under a
  group's directory (tests, examples, assets) lights the group; the rest is counted as "outside
  the code". In the replay 60% of changed files are not module files.
- **The existing group boxes stay** as the "Runs" tab; "System" and "Data" are new tabs.
- **The guide is part of the page**, runs on the replayed data and can be reopened.

## The map contract

`GET /api/map?repo=<name>` returns:

```json
{
  "repo": "blyte",
  "languages": ["rust"],
  "groups": [{"id": "blyte-agent", "kind": "crate", "path": "crates/blyte-agent", "lang": "rust"}],
  "units": [{"id": "blyte_agent::state", "group": "blyte-agent", "file": "crates/blyte-agent/src/state.rs", "lang": "rust"}],
  "edges": [{"from": "blyte_agent::run", "to": "blyte_agent::state", "level": "unit"},
            {"from": "blyte-agent", "to": "blyte-provider", "level": "group"}],
  "structures": [{"id": "blyte_agent::state::State", "name": "State", "kind": "struct",
                  "unit": "blyte_agent::state", "file": "crates/blyte-agent/src/state.rs", "line": 52,
                  "serialisable": true,
                  "fields": [{"name": "runtime", "type": "Runtime"}],
                  "referenced_by": ["blyte_agent::run"]}],
  "unparsed": [{"file": "src/broken.rs", "reason": "expected `;`"}],
  "unresolved": [{"file": "lab/a.py", "line": 10, "reference": "lab.missing"}]
}
```

`kind` of a group is `crate` or `package`; of a structure `struct`, `enum`, `dataclass`, `model`
or `typeddict`. Paths are relative to the repository root with `/`. Every list is sorted (groups,
units and structures by `id`; edges by `level`, `from`, `to`; `unparsed` by `file`; `unresolved`
by `file`, `line`, `reference`) and holds no duplicates. `referenced_by` is sorted and never holds
the structure's own unit. A `group` edge never joins a group to itself; a `unit` edge never joins a
unit to itself.

Rules for all tasks: no fallbacks (a missing or unreadable input is an error that names it, or
an entry in `unparsed`/`unresolved`; never a default, a guess or a silent skip). Add no comments
to code. No job here runs longer than seconds, so nothing needs to be resumable. Existing tests
pass unmodified unless the task says otherwise.

### Task MAP1: map types and the Rust extractor

**Depends on:** none. **Siblings:** MAP2 adds the Python extractor, MAP3 the `/api/map` route,
MAP4 the page's map tabs and MAP5 the guide; none of them is in this worktree. Do not add
Python handling, a route or page changes here.

**Goal.** A function that builds the map contract above for a Rust repository from its files.

**Files.** Create `crates/blyte-cli/src/map.rs`, `crates/blyte-cli/src/map_rust.rs` and
`crates/blyte-cli/tests/test_map_rust.rs`. Add `pub mod map;` and `pub mod map_rust;` to
`crates/blyte-cli/src/lib.rs`. In `crates/blyte-cli/Cargo.toml` add
`syn = { version = "2", features = ["full", "visit"] }`, `quote = "1"` and
`proc-macro2 = { version = "1", features = ["span-locations"] }`. `Cargo.lock` may change.
Change no other file.

**What to build.**

In `map.rs`, serialisable (`serde::Serialize`), `Debug`, `Clone`, `PartialEq` types matching the
contract: `Map { repo, languages, groups, units, edges, structures, unparsed, unresolved }`,
`Group { id, kind, path, lang }`, `Unit { id, group, file, lang }`, `Edge { from, to, level }`,
`Structure { id, name, kind, unit, file, line, serialisable, fields, referenced_by }`,
`Field { name, type }` (Rust field `ty`, serialised as `type`), `Unparsed { file, reason }`,
`Unresolved { file, line, reference }`, and `Part { groups, units, edges, structures, unparsed,
unresolved }` (`Default`), which one language's extractor returns. All text fields are `String`,
`line` is `u32`, `serialisable` is `bool`.

- `pub fn build(root: &Path, repo: &str) -> Result<Map, String>`: if `root/Cargo.toml` exists,
  call `map_rust::extract(root)?` and return a map with `languages = ["rust"]`. Otherwise return
  `Err` with exactly `no supported language in <root>: no Cargo.toml at the root`. Sort and
  de-duplicate every list as the contract says (in a `pub fn finish(repo: &str, languages:
  Vec<String>, parts: Vec<Part>) -> Map` that MAP2 will reuse).

In `map_rust.rs`, `pub fn extract(root: &Path) -> Result<crate::map::Part, String>`:

- **Crates.** Read `root/Cargo.toml` with `toml`. With `[workspace] members`: each member is a
  literal directory or a pattern ending in `/*` (every direct child directory holding a
  `Cargo.toml`), minus `[workspace] exclude`; any other pattern is an `Err` that names it. With
  `[package]` at the root, the root is also a crate. A manifest that cannot be read or parsed is
  an `Err` naming the file. Each crate is a group: `id` the package name, `kind` `crate`, `path`
  its directory (`.` for the root).
- **Targets.** The library root is `[lib] path` or `src/lib.rs` when that file exists; its name
  is `[lib] name` or the package name with `-` replaced by `_`. Binary roots are each
  `[[bin]] path` (name from `[[bin]] name`), or `src/main.rs` when it exists and no `[[bin]]` is
  given (name: the package name).
- **Units.** The library root file is the unit `<lib name>`; a binary root is `bin:<bin name>`.
  From each root, follow `mod x;` items (not `mod x { .. }`): from a root or a `mod.rs` file the
  module file is `x.rs` or `x/mod.rs` beside it; from another file `a.rs` it is `a/x.rs` or
  `a/x/mod.rs`; `#[path = ".."]` overrides, relative to the declaring file's directory. The unit
  is `<parent id>::x`. Skip items under `#[cfg(test)]`. A `mod x;` whose file does not exist is an
  `unresolved` entry (`reference` = `mod x`) and no unit. A file that `syn::parse_file` rejects is
  a unit with no edges plus an `unparsed` entry with the parser's message.
- **Unit edges.** In each file, outside `#[cfg(test)]` items, take every path in `use` trees
  (expanding groups; a glob counts as its prefix) and every `syn::Path` in the code
  (`syn::visit::Visit`). A path counts when its first segment is `crate` (the root of the tree
  the file is in), `self` or `super` (relative to the file's module, counting enclosing inline
  modules), or the library name of a crate in this repository. Resolve it to the unit matching
  the longest prefix of its segments. When that unit is a library root and the next segment is a
  name the root re-exports with `pub use a::b::Name` or `pub use a::b::{..}`, resolve to the unit
  `a::b` instead (one hop only). Emit `{from: this unit, to: that unit, level: "unit"}` unless they
  are the same. Paths starting with anything else are outside the repository and are ignored.
- **Group edges.** For each crate, each entry of `[dependencies]` that has a `path`, or has
  `workspace = true` and a `path` in the root's `[workspace.dependencies]`, pointing at another
  crate of this repository: `{from: this package, to: that package, level: "group"}`.
- **Structures.** Every `struct` and `enum` at file level or inside inline modules, outside
  `#[cfg(test)]` items, not inside function bodies. `id` is `<unit id>::<Name>` (with the inline
  module names between, if any). `line` is the 1-based line of the item's name.
  `serialisable` is true when a `#[derive(..)]` on it lists a path whose last segment is
  `Serialize` or `Deserialize`. Fields: named fields by name; tuple fields named `0`, `1`, …;
  enum variants by name with type `` for a unit variant, `(A, B)` for a tuple variant and
  `{a: A, b: B}` for a struct variant. A type is written as rustfmt would write it:
  `Vec<String>`, `Option<PathBuf>`, `HashMap<String, u64>`, `&'static str`, `Box<dyn Fn(u32) -> bool>`.
- **References.** A unit refers to a structure when one of its counted paths resolves to the
  structure's unit (directly or through the one-hop re-export) and the next segment is the
  structure's name, including names inside `use` groups. Two structures with the same name in
  different units stay separate.

**Tests** (`crates/blyte-cli/tests/test_map_rust.rs`; each builds its repository in a
`tempfile::tempdir()` by writing files; run with `cargo test -p blyte --test test_map_rust`):

4. `module_files_resolve`: `mod a;` (`a.rs`), `mod b;` (`b/mod.rs`), `a.rs` holding `mod c;`
   (`a/c.rs`) and `#[path = "odd/d.rs"] mod d;`: units `x`, `x::a`, `x::a::c`, `x::b`, `x::d` with
   the right files.
5. `lib_name_and_bin_units`: package `my-tool` with `[lib] name = "tool_lib"`, `src/lib.rs` and

6. `edges_from_use_and_inline_paths`: a file with `use crate::a::Thing;`, a nested
   `use crate::{b, a::c::{Other, self}};`, an inline call `crate::d::go()` and `super::b::x()`:

7. `cross_crate_edge_and_reexport`: crate `one` has `pub use inner::deep::Item;` in `lib.rs`;

13. `build_sorts_and_names_languages`: `map::build` on a two-crate workspace: `languages` is

### Task MAP2: the Python extractor

**Depends on:** MAP1 (dispatch on its branch). **Siblings:** MAP3 adds the `/api/map` route and
MAP4 the page's map tabs; neither is in this worktree. Do not add a route or page changes.

**Goal.** `map::build` also maps Python code, by scanning lines, with no added dependency
beyond `ignore`.

**Files.** Create `crates/blyte-cli/src/map_python.rs` and
`crates/blyte-cli/tests/test_map_python.rs`. Add `pub mod map_python;` to
`crates/blyte-cli/src/lib.rs`, `ignore.workspace = true` to `crates/blyte-cli/Cargo.toml`, and
change `build` in `crates/blyte-cli/src/map.rs`. Change no other file (do not change
`comment_lint.rs`; write the string and comment stripping in `map_python.rs`).

**What to build.**

`pub fn extract(root: &Path) -> Result<crate::map::Part, String>` in `map_python.rs`:

- **Files.** Walk `root` with `ignore::WalkBuilder` (so ignored files are left out), taking
  `*.py` files, leaving out any path with a directory named `tests`, `test`, `.venv`, `venv`,
  `__pycache__` or `node_modules`, and files named `test_*.py`, `*_test.py` or `conftest.py`.
- **Units and groups.** A file's dotted name is its path from the root without `.py`, with `/`
  as `.`; when `root/src` is a directory, a leading `src.` is dropped. `pkg/__init__.py` is the
  unit `pkg`; `pkg/mod.py` is `pkg.mod`. A group is each directory holding at least one unit:
  `id` the directory's dotted name (`.` for the root; the leading `src` dropped the same way),
  `kind` `package`, `path` the directory (`.` for the root). A unit's group is its directory's.
- **Scanning.** Before reading statements, blank out comments and the contents of string
  literals (single, double, triple-quoted, with prefixes such as `r`, `b`, `f`), keeping line
  numbers. Join lines continued by `\` or by open parentheses.
- **Imports.** `import a.b`, `import a.b as c`, `from a.b import x, y as z`, `from . import x`,
  `from ..a import x`, at any indentation. Resolve in this order: relative imports against the
  file's package (one level up per extra dot; above the root is `unresolved`); otherwise the
  dotted name from the root; otherwise the dotted name from the importing file's own directory
  (Python puts a script's directory on its path). For `from M import n`, the target is the unit
  `M.n` when it exists, otherwise the unit `M`; for `import a.b.c`, the unit matching the longest
  prefix. An import whose first name is not a top-level name in the repository is outside it and
  is ignored. One whose first name is in the repository but which resolves to no unit is an
  `unresolved` entry (`reference` = the dotted name as written, with its leading dots).
  Emit `unit` edges (no self edges), and a `group` edge for every unit edge that crosses groups.
- **Structures.** Classes at column 0: `dataclass` when decorated with `@dataclass`,
  `@dataclasses.dataclass` or either with arguments; `model` when a base's last name is
  `BaseModel`; `typeddict` when a base's last name is `TypedDict`. Others are not structures.
  `serialisable` is true. Fields are the `name: Type` lines at the class body's indentation
  (the type is the text up to `=` or the end, trimmed), leaving out `ClassVar[..]` fields.
  `id` is `<unit>.<Name>`, `line` the `class` line.
- **References.** A unit refers to a structure when it has `from M import Name` resolving to the
  structure's unit, or to a package `__init__` that itself imports that `Name` from the
  structure's unit (one hop); or when it imports the structure's unit as a name
  (`import a.b as c`, `from a import b`, `import a.b`) and its code has `<that name>.Name`.

`map::build`: run the Rust extractor when `root/Cargo.toml` exists and the Python extractor
when it returns at least one unit; `languages` lists those that ran, in the order `rust`,
`python`. When neither applies, `Err` with exactly
`no supported language in <root>: no Cargo.toml at the root and no Python modules`. Update
MAP1's test `build_without_cargo_toml_is_an_error` to this text; change no other existing test.

**Tests** (`crates/blyte-cli/tests/test_map_python.rs`, repositories written into a
`tempfile::tempdir()`; run with `cargo test -p blyte --test test_map_python`):

1. `modules_packages_and_groups`: `pkg/__init__.py`, `pkg/a.py`, `pkg/sub/b.py`, `tool.py`:
   units `pkg`, `pkg.a`, `pkg.sub.b`, `tool`; groups `.`, `pkg`, `pkg.sub` with the right paths.
2. `src_layout_drops_src`: `src/pkg/a.py`: unit `pkg.a`, group `pkg` with path `src/pkg`.
3. `tests_and_virtualenvs_are_left_out`: `tests/test_a.py`, `pkg/test_b.py`, `pkg/conftest.py`,
   `.venv/lib/x.py`: none is a unit.
4. `absolute_and_relative_imports`: `import pkg.a`, `from pkg import a`, `from pkg.a import f`,
   `from . import a`, `from ..other import g`, a parenthesised multi-line `from`, and an import
   indented inside a function: the exact edges.
5. `script_directory_import`: `scripts/run.py` with `from helper import h` and
   `scripts/helper.py`: edge `scripts.run -> scripts.helper`.
6. `outside_imports_ignored_inside_unresolved`: `import os`, `from requests import get` give
   nothing; `from pkg.nothere import x` gives an `unresolved` entry with file, line and
   `pkg.nothere`; `from ... import x` from a top-level module gives one with `...`.
7. `imports_in_strings_and_comments_are_ignored`: `# import pkg.a`, a docstring holding
   `from pkg import a`, and `s = "import pkg.a"`: no edge.
8. `structures_and_fields`: `@dataclass`, `@dataclasses.dataclass(frozen=True)`,
   `class M(BaseModel)`, `class T(TypedDict)`, a plain class, and a dataclass indented inside a
   function: three kinds found with exact fields (a default value dropped, a `ClassVar` field
   left out) and lines; the plain and the nested class absent.
9. `references_direct_reexported_and_by_module`: `from pkg.models import Rec`; `from pkg import
   Rec` where `pkg/__init__.py` has `from .models import Rec`; `import pkg.models as m` with
   `m.Rec(`: all three units are in `referenced_by`; a unit importing only `pkg.models.other` is
   not.
10. `group_edges_cross_packages_only`: edges inside one package give no group edge; one across
    packages gives exactly one.
11. `build_python_only_and_mixed`: `map::build` on a Python-only repository gives
    `languages == ["python"]`; with a `Cargo.toml` crate added, `["rust", "python"]` and units of
    both; on an empty directory the exact `Err` text.

**Commit message:** `feat(map): map Python packages, imports and data classes`

### Task MAP4: the map tabs in the mock page

**Depends on:** none (it is written against the map contract in this plan). **Siblings:** MAP1
to MAP3 build and serve `/api/map`; they are not in this worktree, so the page cannot be tried
against a server here. MAP5 adds the guide afterwards; do not add one.

**Goal.** The right-hand pane of the mock shows the system map and the data map of a
repository, with the replay's runs lit on them.

**Files.** Change `crates/blyte-cli/assets/mock/index.html` and
`crates/blyte-cli/tests/test_mock_page.rs` (add tests; existing tests unmodified). The page
stays one self-contained file: no network resources, no libraries, colours only through the
existing custom properties so light and dark both work.

**What to build.**

- **Tabs.** In the right pane's head, three tabs in `#map-tabs`: `Runs` (the group boxes drawn
  today in `#map`, unchanged, and the default), `System` (`#map-system`) and `Data`
  (`#map-data`). Next to them a repository select `#map-repo` listing the replay's repositories
  by number of runs, the largest first and selected; and a toggle `#map-wide` that widens the
  right pane to about 60% of the window and back.
- **Loading.** On first opening `System` or `Data` for a repository, fetch
  `/api/map?repo=<name>` (name URL-encoded) and keep the answer for that repository. While
  waiting show `reading the code`. On a non-200 answer show the `error` text from the body as
  it is, and nothing else in that tab; do not draw a partial or stand-in map.
- **System tab.** Groups as boxes with their `id`, `kind` and unit count, and `group` edges as
  lines. Clicking a group opens it (one open at a time; clicking again closes it): its units are
  drawn as boxes inside it, labelled with the last part of their `id`, laid out in columns by
  dependency depth among the open group's units (a unit sits one column after the deepest unit
  it depends on; cycles are broken by `id` order), with `unit` edges drawn in SVG. Edges to
  units of other groups end at that group's collapsed box. Edges are faint by default; hovering
  or clicking a unit draws its own edges strongly, dims the rest and shows in `#map-detail` the
  unit's `id`, `file`, what it depends on, what depends on it, and the structures it defines.
- **Data tab.** Structures of the selected repository, grouped under their unit, each showing
  `name`, `kind` and the number of units referring to it. By default only `serialisable` ones; a
  checkbox `#map-data-all` shows the rest. Clicking a structure shows in `#map-detail` its `id`,
  `file:line`, its fields (name and type) and the units in `referenced_by`. Under the tab title,
  the line: `Shows references written in the code. Uses through an inferred type are not shown.`
- **Notes.** `#map-notes` shows `<n> files not parsed` and `<n> references not resolved` when
  either is above zero; clicking it lists them (`file`, and `reason` or `line` and `reference`).
- **Overlay.** For the selected repository, at the replay clock's current time, for each run in
  progress and each run waiting for a decision, place each of its `changed_files`: on the unit
  whose `file` equals the path; otherwise on the group whose `path` is the longest directory
