# V1 mock: replay real runs through the one surface

Date: 2026-11-20. Spec: `docs/specs/2026-11-20-blyte-v1.md`, "Order of work" step 1.

## Goal

`blyte mock` opens a local page that replays the last week of real blyte runs through the V1
surface (conversation, map, review queue), so the queue and its interaction with the
conversation (decisions 5 and 6) can be tried before the session server is built. The page
records what the developer does in it and can save that record.

## Decisions

- **The mock is a page served by blyte**, like the dashboard: one self-contained HTML file,
  bundled fonts, nothing from the network. The desktop shell comes with step 2.
- **The replay data is built in Rust and tested**; the page only draws it. Each run carries its
  queue classification (`card`) and its group, so no rule lives only in JavaScript.
- **Group is a stand-in.** The design elements of decision 5 do not exist yet, so a run's group
  is the directory most of its changed files are in. This is the documented value for the mock.
- **Nothing is guessed.** A run that lacks a field the replay needs is left out and listed under
  `skipped` with the reason. The page shows the number skipped.
- **Clean or exception needs recorded checks.** `.wt/<id>.checks.json` exists only for runs that
  were reviewed. A run without it is an exception card that says "checks not recorded".
- **Conversation, map focus, check-ins and the now-or-later offer are not recorded today**, so
  the page creates them as the developer uses it. Orchestrator replies are a fixed line.
- **Limits warn only**: 3 runs in progress, 7 groups waiting. Both are constants at the top of
  the page's script.

Found by research run R-MOCK1 (2026-11-20): changed line counts are not recorded, so groups do
not split by size in the mock; `finished` is not a recorded time, so it is `started_at` plus the
recorded `seconds`.

## The replay contract

`GET /api/replay` returns:

```json
{
  "exported_at": 1763683200,
  "window_days": 7,
  "skipped": [{ "key": "blyte/T9", "reason": "no summary file" }],
  "runs": [
    {
      "key": "blyte/T1", "id": "T1", "repo": "blyte", "research": false,
      "title": "short task title", "task": "task text, at most 2000 characters",
      "plan_file": "docs/plans/x.md", "plan_task": "Task T1",
      "started_at": 1763100000, "finished_at": 1763100420,
      "outcome": "verified", "final_message": "the implementer's report",
      "turns": 18, "cost_usd": 0.14,
      "commits": [{ "sha": "abc1234", "subject": "feat: x" }],
      "changed_files": ["crates/blyte-cli/src/dispatch.rs"],
      "group": "crates/blyte-cli",
      "checks_recorded": true, "flags": [],
      "card": "clean",
      "verdict": "accepted", "verdict_notes": "", "verdict_ts": 1763100560
    }
  ]
}
```

`runs` is sorted by `started_at`, then `key`. `plan_file`, `plan_task`, `final_message`,
`cost_usd`, `group`, `verdict`, `verdict_notes` and `verdict_ts` are `null` when not recorded.

### Task M1: build the replay data

**Depends on:** none. **Siblings:** M2 adds the page `crates/blyte-cli/assets/mock/index.html`
separately and M3 adds the `blyte mock` command afterwards; neither is in this worktree. Do not
add a page, a route or a command here.

**Goal.** A function that turns the recorded runs of the last N days into the replay contract
above, so the mock page has tested data to draw.

**Files.** Create `crates/blyte-cli/src/replay.rs` and `crates/blyte-cli/tests/test_replay.rs`.
Add `pub mod replay;` to `crates/blyte-cli/src/lib.rs`. Change no other file.

**What to build.**

```rust
#[derive(Debug, Serialize, PartialEq)]
pub struct Replay { pub exported_at: u64, pub window_days: u64, pub skipped: Vec<Skipped>, pub runs: Vec<Run> }
#[derive(Debug, Serialize, PartialEq)]
pub struct Skipped { pub key: String, pub reason: String }
pub struct Run { /* the fields of the contract above, in that order, derive Debug, Serialize, PartialEq */ }

pub fn collect(src: &crate::dashboard::Sources, now: u64, days: u64) -> Replay;
pub fn group_of(changed_files: &[String]) -> Option<String>;
pub fn card_of(outcome: &str, checks_recorded: bool, flags: &[String]) -> &'static str;
```

- `collect` calls `crate::dashboard::collect_jobs` with a copy of `src` whose `hours` is
  `days * 24`, and builds one `Run` per job from the `Job` fields (`key`, `id`, `repo`,
  `research`, `title`, `task`, `plan_file`, `plan_task`, `started_at`, `turns`, `cost_usd`,
  `commits`, `changed_files`, `verdict`, `verdict_notes`, `verdict_ts`).
- From `<root>/.wt/<id>.json` (the dispatch summary; `root` is the job's `root`) it reads
  `outcome`, `seconds` and `final_message`. `finished_at` is `started_at + seconds`, with
  `seconds` rounded down to whole seconds.
- From `<root>/.wt/<id>.checks.json` it reads `flags` (an array of strings). File present:
  `checks_recorded` is true. File absent: `checks_recorded` is false and `flags` is empty.
- A job is left out of `runs` and added to `skipped` with exactly these reasons, checked in this
  order: `"still running"` (status `running`), `"no root"`, `"no start time"`,
  `"no summary file"` (`.wt/<id>.json` missing), `"summary unreadable: <error>"` (not JSON, or
  `outcome` or `seconds` missing), `"checks unreadable: <error>"` (the checks file exists but is
  not JSON or has no `flags` array). No fallbacks: never substitute a default, a file's
  modification time or an empty value for something missing.
- `group_of`: for each file, its group is `crates/<name>` when the path starts with `crates/`
  and has at least three components, otherwise its first path component when the path has at
  least two components, otherwise `"."`. The result is the group with the most files; a tie goes
  to the group that sorts first. No files: `None`.
- `card_of`: `"clean"` when `outcome == "verified"`, `checks_recorded` is true and `flags` is
  empty; otherwise `"exception"`.
- `runs` sorted by `started_at`, then `key`; `skipped` sorted by `key`.

**Tests** (`cargo test -p blyte --test test_replay`). Build a temporary repository directory
with a `.wt` folder by hand, the way `crates/blyte-cli/tests/test_dashboard.rs` does, and pass
it as `Sources { roots, runs_dirs: vec![], hours: 0 }`.

1. `group_of`: `["crates/a/src/x.rs", "crates/a/src/y.rs", "docs/z.md"]` gives `crates/a`;
   `["docs/a.md", "src/b.rs"]` gives `docs` (tie, sorts first); `["README.md"]` gives `.`;
   `["crates/README.md"]` gives `crates`; `[]` gives `None`.
2. `card_of`: (`verified`, true, no flags) is `clean`; (`verified`, false, no flags) is
   `exception`; (`verified`, true, one flag) is `exception`; (`gate_failed`, true, no flags) is
   `exception`.
3. A verified run with a summary (`seconds: 420.9`), a checks file with empty `flags` and a
   verdict file appears in `runs` with `finished_at == started_at + 420`, `card == "clean"`,
   `checks_recorded == true`, and the verdict, notes and verdict time from the verdict file.
4. A run with no checks file has `checks_recorded == false`, empty `flags` and
   `card == "exception"`.
5. A run with a start file and no summary file is absent from `runs` and present in `skipped`
   with reason `no summary file`.
6. A summary file containing `not json` gives a `skipped` reason starting `summary unreadable:`.
7. A checks file containing `{}` gives a `skipped` reason starting `checks unreadable:`.
8. Two runs started at different times come back in `started_at` order whatever their ids.
9. A run started 8 days before `now` is absent from both lists when `days` is 7.
10. `serde_json::to_value` of a `Run` has exactly the keys of the contract above.

**Constraints.** Existing tests pass unmodified. Add no comments. No fallbacks. Nothing here
runs long, so resumability does not apply.

**Commit message:** `feat(mock): build replay data from recorded runs`

### Task M2: the mock page

**Depends on:** none. **Siblings:** M1 builds the data in `crates/blyte-cli/src/replay.rs` and
M3 adds the `blyte mock` command and its routes; neither is in this worktree. Do not add Rust
code other than the test file named here.

**Goal.** One self-contained page that replays the contract above as the V1 surface and records
what the developer does.

**Files.** Create `crates/blyte-cli/assets/mock/index.html` and
`crates/blyte-cli/tests/test_mock_page.rs`. Change no other file.

**What to build.** One HTML file with inline `<style>` and `<script>`, no framework, no build
step. Copy the `@font-face` rules, colour tokens and light and dark themes from
`crates/blyte-cli/assets/dashboard/index.html` (fonts are served at the same `/fonts/...`
paths). On load it fetches `/api/replay` once. If the fetch fails or the body is not the
contract, it shows the error text in the page and nothing else; it never shows sample data.

Layout, in one window:

- **Top bar** (`id="bar"`): the replay clock (date and time of the replay position); play and
  pause (`id="play"`); speed, one of 60x, 600x, 3600x (`id="speed"`); "next arrival"
  (`id="next"`), which jumps the clock to the next `finished_at`; a slider over the whole
  window (`id="clock"`); runs in progress as `n / 3` (`id="wip"`); groups waiting as `n / 7`
  (`id="waiting"`); session length since the page opened (`id="session"`); the number of
  skipped runs (`id="skipped"`). `wip` and `waiting` take a warning colour past their limit
  and block nothing. The limits are `const WIP_CAP = 3` and `const QUEUE_BOUND = 7`.
- **Mode switch** (`id="mode"`): "Design" and "Review (n)", where n is the number of undecided
  arrived runs. This count is the only thing an arrival changes on screen in Design mode.
- **Left pane, Design mode** (`id="conversation"`): a thread and an input. A run's dispatch
  adds one line ("dispatched T1: title"). An arrival adds nothing. A message the developer
  types is added, followed by the fixed reply "(mock) the orchestrator would answer here". When
  a map element is focused, the input shows "about <group>".
- **Left pane, Review mode** (`id="queue"`): arrived, undecided runs grouped by `group` (runs
  with `group` null go under "no files changed"). In each group:
  - every `card: "clean"` run is one line: id, title, an Accept button; with two or more, an
    "Accept all clean (n)" button;
  - every `card: "exception"` run is a card of fixed height: id, title, outcome, the first
    three `flags` and "+n more", or "checks not recorded" when `checks_recorded` is false; and
    four actions: Accept, Send back, Redo, Hold. Send back and Hold require a one-line note
    before they apply. A held run stays in the queue showing its note first;
  - a "Details" control per run, closed by default, showing `final_message`, `task`,
    `changed_files` and `commits`;
  - a short thread for the group with its own input and the same fixed reply; it disappears
    when the group has no undecided runs;
  - after a decision the line shows "recorded then: <verdict>" when `verdict` is not null.
- **Right pane** (`id="map"`): one box per group seen anywhere in the replay window, showing
  the group name, runs in progress and runs waiting for review at the replay position.
  Clicking a box focuses it (clicking again clears it); the queue scrolls to that group.
- **Entering Review** opens a check-in (`id="checkin"`): two scales from 1 to 5, "focus" and
  "tiredness", with Continue and Skip, and one line offering an optional one-minute pause.
- **The negotiated exception** (`id="offer"`): in Design mode, when an `exception` run arrives
  whose `group` is the focused map element, one line appears under the thread: "<id> touches
  <group> and needs a decision", with Now (switches to Review at that group) and Later
  (dismisses it). It appears for nothing else.
- **Record** (`id="save"`): every action is appended to an array kept in `localStorage` under
  `blyte-mock-log` (wrap every access in try/catch; the page works without it): mode switches,
  decisions (run key, action, note, seconds since the run was first shown in the queue),
  details opened, focus changes, check-ins, now or later, each with the real time and the
  replay time. "Save record" downloads it as `blyte-mock-log.json`; "Clear record" empties it.

Replay rule: at replay time `t`, a run is in progress when `started_at <= t < finished_at`,
arrived when `finished_at <= t`, and not yet shown when `t < started_at`. Moving the slider
backwards does not undo decisions.

**Tests** (`cargo test -p blyte --test test_mock_page`), with
`const PAGE: &str = include_str!("../assets/mock/index.html");`:

1. The page contains `/api/replay`, `<html` and `prefers-color-scheme: dark`, and none of
   `http://`, `https://`, `//fonts.`, `<link rel="stylesheet"`, `<script src`.
2. It contains each of `id="bar"`, `id="play"`, `id="speed"`, `id="next"`, `id="clock"`,
   `id="wip"`, `id="waiting"`, `id="session"`, `id="skipped"`, `id="mode"`,
   `id="conversation"`, `id="queue"`, `id="map"`, `id="checkin"`, `id="offer"`, `id="save"`.
3. It contains `const WIP_CAP = 3` and `const QUEUE_BOUND = 7`.
4. It contains each contract field name the page reads: `started_at`, `finished_at`, `card`,
   `group`, `checks_recorded`, `flags`, `final_message`, `changed_files`, `verdict`, `skipped`.
5. It contains `blyte-mock-log`, `checks not recorded`, `recorded then:`, `Accept all clean`,
   `Send back`, `Hold`, `Redo`, `Now`, `Later`.
6. It does not contain `sample` or `lorem` in any letter case.

Also run `node --check` on the script if `node` is installed (extract the `<script>` body to a
temporary file outside the repository); a syntax error there is a failure to fix.

**Constraints.** Existing tests pass unmodified. Add no comments. No fallbacks: a missing
contract field is an error shown in the page, never a default.

**Commit message:** `feat(mock): the V1 surface as a replay page`

### Task M3: the `blyte mock` command

**Depends on:** M1, M2 (dispatch with `--base` on the branch that holds both).

**Goal.** `blyte mock` serves the page and the replay data on a local port.

**Files.** Create `crates/blyte-cli/src/mock.rs` and `crates/blyte-cli/tests/test_mock.rs`.
Change `crates/blyte-cli/src/cli.rs` (a `Mock(MockArgs)` command next to `Dashboard`),
`crates/blyte-cli/src/main.rs` (run it, as `Dashboard` is run) and
`crates/blyte-cli/src/lib.rs` (`pub mod mock;`). If the dashboard's request-serving loop is
private, make the smallest part of it `pub(crate)` in `crates/blyte-cli/src/dashboard.rs` and
reuse it; do not copy it.

**What to build.**

- `MockArgs`: `--port` (default `7272`), `--days` (default `7`, must be 1 to 31; anything else
  is an error naming the value), and the same `--root` option the dashboard takes, read the
  same way (`Sources::from_args_with_where` or the function `dashboard::run` uses).
- `pub fn route(path: &str, src: &Sources, now: u64, days: u64) -> (u16, &'static str, Vec<u8>)`:
  `/` and `/index.html` give `assets/mock/index.html`; `/favicon.svg` and the three
  `/fonts/*.woff2` paths give the dashboard's assets; `/api/replay` gives
  `replay::collect(src, now, days)` as JSON; anything else is 404. A serialisation failure is
  a 500 with the error text, not an empty body.
- `pub fn run(args: &MockArgs) -> i32`: binds `127.0.0.1:<port>`, prints the address, serves
  GET only with `Cache-Control: no-store` on `/api/replay`. A port already in use is an error
  naming the port, exit 1.

**Tests** (`cargo test -p blyte --test test_mock`):

1. `route("/", ...)` is 200, `text/html; charset=utf-8`, and its body contains `id="queue"`.
2. `route("/api/replay", ...)` over a temporary repository holding one finished run is 200,
   `application/json`, and parses to an object whose `runs` has one entry with that id and
   whose `window_days` equals the `days` passed.
3. `route("/fonts/archivo.woff2", ...)` is 200 with a non-empty body; `route("/nope", ...)`
   is 404.
4. Running the binary with `mock --days 0` exits non-zero and its error output contains `0`.

**Constraints.** Existing tests pass unmodified. Add no comments. No fallbacks.

**Commit message:** `feat(mock): serve the replay page with blyte mock`
