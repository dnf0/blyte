# Plan: notice and stop a run that keeps re-reading without changing anything (2026-10-19)

## Why

Run C1 (2026-10-19, `docs/plans/2026-10-19-claim-check.md`) made 1,160 reads over 254 turns and
not one edit. Every turn it read the same five large files whole; folding dropped them; the next
turn read them again. Nothing in blyte noticed. Decision (user, 2026-10-19): detect it in the
agent loop.

Rule: a **repeat** is a `read`, `grep` or `glob` call whose name and arguments (the JSON
`arguments`, serialized) equal an earlier call made since the workspace last changed. The
workspace changes on any `edit`/`write` tool call that succeeded, or when `self.fingerprint()`
(`run.rs`, `fn fingerprint`) differs from the value at the previous check (catches `bash` edits).
- On the 3rd and later occurrence of the same call, append a harness note to that tool result:
  `[blyte] You have made this exact call {n} times since the workspace last changed; earlier results were dropped from your context to save space. Do not read it again: note what you need from it in your reply, read only the lines you need, and make your change.`
- When repeats since the last change reach 60, end the run: outcome `BudgetExhausted` (so callers
  treat it like any budget stop), with `report.read_loop = true`.

### Task L2: fold-thrash detection and a per-turn read-volume warning (parallel with L1)

Why: the fold loop has now happened twice (R-sota at 48k on 2026-10-18; C1 on 2026-10-19). The
cause both times: one turn's tool output was about a whole fold budget, so the next fold removed
the previous turn's results before the model used them. L1 catches the repeats it causes; L2
catches the cause, whatever the model reads. **L1 is changing the tool-execution loop in
`run_loop` (about lines 940-1000) at the same time: do not edit that block.** Read only the ranges
named; never read `run.rs` whole.

Files: `crates/blyte-agent/src/context.rs`, `crates/blyte-agent/src/run.rs` (only the places named
below), `crates/blyte-cli/src/report.rs`, new test `crates/blyte-agent/tests/test_fold_thrash.rs`,
the doc that describes folding (`grep -rln "fold" docs/*.md`, one sentence).

1. **context.rs:** make `approx_tokens` (line 65) `pub` so `run.rs` can measure a turn's output.
   `ContextStrategy::folds(history)` (line ~20 default, ~200 for `Folded`) returns `(a, b)` ranges in
   `rest` coordinates, i.e. `history[1..]`: `rest[a..b]` is folded, which is `history[a+1..b+1]`.
2. **run.rs, per turn** (the turn loop starts at `for turn in 1..=self.budget.max_turns`, about line
   763; the request is built and `let fold_budget = self.context.fold_budget(history);` is at about
   line 825; read 760-830). Keep `prev_turn_start: Option<usize>` = `history.len()` at the start of
   the previous turn. Just before the request is sent, compute the folds; if the last fold's end
   (`b + 1` in history coordinates) is greater than `prev_turn_start`, the previous turn's results
   are being folded: `thrash += 1`, else `thrash = 0`.
   - When `thrash` reaches 2, push (once per streak) a `Message::User` note before the request is
     built, so it is in this turn's prompt:
     `[blyte] Your recent tool results are being dropped from your context because each turn reads more than fits (about {budget} tokens stay verbatim). Read narrower ranges (at most 200 lines), one or two files per turn, and act on what you have read before reading more.`
     (Push the note and rebuild the request if that is simpler than reordering.)
   - When `thrash` reaches 5: `report.fold_thrash = true`, return `(Outcome::BudgetExhausted, report)`.
3. **run.rs, read volume:** at the start of each turn (same place), sum `approx_tokens` over the
   messages the previous turn added (`history[prev_turn_start..]`, tool results only). If it is more
   than half of `fold_budget` (skip when `fold_budget` is `None`), push once per 5 turns:
   `[blyte] Your last turn's tool output was about {n} tokens, more than half of what stays in context ({budget}). Read narrower ranges so it is not dropped before you use it.`
   and add 1 to `report.big_read_turns`.
4. **Report:** `RunReport` (`pub struct RunReport`, about line 107; near `truncated_turns`):
   `pub fold_thrash: bool`, `pub big_read_turns: u32`, serialized like `truncated_turns`; mirror in
   `crates/blyte-cli/src/report.rs` like `truncated_turns` (about lines 73, 140, 191).
   (Not the review printer; L1 is editing `dispatch.rs` near there.)
5. **Tests** (`test_fold_thrash.rs`; copy the scripted provider and runner setup from

   `claim_check: false`; use `Folded { budget_tokens: 2_000 }` and a file of about 3,000 tokens):

   - small reads every turn: no note, `fold_thrash == false`, `big_read_turns == 0`;
