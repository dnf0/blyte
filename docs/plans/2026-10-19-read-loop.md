# Plan: notice and stop a run that keeps re-reading without changing anything (2026-10-19)

## Why

Run C1 (2026-10-19, `docs/plans/2026-10-19-claim-check.md`) made 1,160 reads over 254 turns and
not one edit. Every turn it read the same five large files whole; folding dropped them; the next
turn read them again. Nothing in blyte noticed. Decision (user, 2026-10-19): detect it in the
agent loop.

Rule: a **repeat** is a `read`, `grep` or `glob` call whose name and arguments (the JSON
`arguments`, serialized) equal an earlier call made since the workspace last changed. The
workspace changes on any `edit`/`write` tool call that succeeded, or when `self.fingerprint()`
(`run.rs`, `fn fingerprint`) differs from the value at the previous check (catches `bash` edits).
- On the 3rd and later occurrence of the same call, append a harness note to that tool result:
  `[blyte] You have made this exact call {n} times since the workspace last changed; earlier results were dropped from your context to save space. Do not read it again: note what you need from it in your reply, read only the lines you need, and make your change.`
- When repeats since the last change reach 60, end the run: outcome `BudgetExhausted` (so callers
  treat it like any budget stop), with `report.read_loop = true`.
