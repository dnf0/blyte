# Remove dead code

A read-only survey (2026-11-27) listed what nothing uses any more: public items the compiler cannot
flag, the hidden `blyte mock` prototype that the surface replaced, the dashboard's reader for a
retired run format, one unused dependency, and unused style rules. This plan removes them. Nothing a
user can see changes, except that the hidden `blyte mock` command is gone.

## Rules for every task

- **Removal only.** No behaviour change, no refactoring, no renaming, no new features.
- **Check before removing.** For each item, search the whole workspace first
  (`rg -n '\bname\b' crates scripts docs README.md .github`). If it has a caller in non-test code,
  leave it in place and say so in your final message. Do not remove it and patch the caller.
- **Tests.** Delete a test only when all it tests is a removed item. When a test uses a removed
  wrapper to reach live code, change it to call the live function named in the task, and keep every
  assertion. Do not weaken, skip or `#[ignore]` any test.
- **Linux-only code cannot be compiled on this machine.** Do not remove or change anything that is
  referenced from code under `#[cfg(target_os = "linux")]` or `#[cfg(not(target_os = "macos"))]`,
  or from `crates/blyte-agent/tests/test_sandbox_linux.rs` or
  `crates/blyte-agent/tests/test_linux_read_allowlist.rs`. If an item in the task is referenced
  there, leave the item and say so.
- **No fallbacks**: do not add defaults, silent skips or compatibility shims for what is removed.
- Touch only the files the task lists. If the task cannot be finished without another file, change
  the minimum there and name the file in your final message.
- The check is `cargo fmt --all --check && cargo clippy --all-targets -- -D warnings` and the tests
  of the crates you changed (`python3 scripts/test-changed.py`).

### Task DC4: the dashboard no longer reads the retired run format

**Depends on:** none. **Siblings:** DC1, DC2, DC3, DC5 run at the same time; their changes are not
here. Touch only `crates/blyte-cli/src/dashboard.rs`, `crates/blyte-cli/assets/dashboard/index.html`,
`docs/usage.md` and the dashboard's own tests.

Before blyte, runs were made by a tool called `agy`, which wrote a summary file `<id>.json` in a
different shape and gave the status `"finished"`. That tool was retired on 2026-10-01 and no such
run directories remain. The dashboard still reads them.

Remove:

1. In `dashboard.rs`: `struct AgySummary` and every branch that reads it or produces the status
   `"finished"`. A run directory with no blyte summary must be handled exactly as the code already
   handles it when the old summary is also absent (read that path first; do not invent a new
   behaviour, and do not add an error or a default).
2. In `assets/dashboard/index.html`: the handling of the `"finished"` status, and these style
   variables, which nothing uses: `--faint`, `--rust-soft`, `--pass`, `--pass-soft`, `--fail`,
   `--fail-soft`, `--amber`, `--amber-soft`, `--merged-soft`, `--lane`. Before removing a variable,
   search the file for `var(--name` and for the bare name in the script; keep any that is used.
3. In `docs/usage.md`: the lines that describe the old summaries and the "Finished" status.
4. Tests that build an old-format summary to check the removed branches (search
   `crates/blyte-cli/tests` for `agy` and `finished`): remove those tests or those fixtures. A test
   that checks something else and merely has `finished` in a fixture gets a current status instead.

Keep the `Job.model` field.

Commit message: `refactor: the dashboard stops reading the retired agy run summaries`
